    Running, checking and browser requirements
    Run code executes locally in a browser worker and pauses at each input() call. Answer in the console and press Enter. Stop also works while waiting. Waiting time does not count toward the 10-second computation limit. Live input needs browser support for JSPI; use a recent Chrome or Edge if your browser reports it is unavailable. Automated tests do not need live input support.
    Check all tests supplies each test’s input automatically, with fresh variables. input() prompts are ignored for marking; other printed text is checked. Text comparison preserves spaces and capitalisation, normalises Windows line endings and ignores one final newline. Numeric-output tasks compare numeric values in order with a small floating-point tolerance. Function tasks check the return value and required type, including tuple/list and Boolean distinctions. All supplied input must be consumed. Test inputs are shown as quoted strings to make empty values and spaces visible; type their contents without the quotes during a live run.
    Exercises and tests come from Programming-Tasks.docx, with explicit output and function contracts where needed. Expected answers are visible in the page source. Checks assess results, not whether you used a requested flowchart, loop, function structure or algorithm; review those separately. The guessing-game tests temporarily fix random.randint(1, 100); live runs use a real random secret.
    The Pyodide runtime downloads from jsDelivr, so an internet connection is required when Python loads. This page does not upload your code or responses. CSS, editor logic, exercise bank and worker code are embedded in this HTML file. Each page is independent. Python is an external dependency; offline availability is not guaranteed.
    Printed output is limited to 20,000 characters per run or test. Live responses have a 10,000-character limit and the displayed transcript a 100,000-character limit. Code drafts and passed-task history are kept in this browser if storage is available. Live responses are not saved. The editor supports Tab indentation, Ctrl/Cmd+Enter, reset undo and .py downloads. Standard input reads other than input() are not connected to the answer box.
    Successful solutions are saved only after every test passes. Returning to a task after reopening this page restores its successful code; later drafts are kept separately and can be restored with Restore latest draft. A failed or stopped check does not replace the successful solution. Earlier pass markers without a verified code copy are retained; recheck once to save the successful code. Storage depends on the browser profile and website address. Clearing browser data removes progress; private browsing or disabled/full storage may prevent it being retained. For reliable persistence, use a consistent website address; storage for locally opened files can vary between browsers.
