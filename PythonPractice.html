    How running and checking work
    The page uses Pyodide, which downloads Python from jsDelivr and runs it in a browser worker. No Python installation or execution server is needed. This page does not upload your code or inputs. The runtime download makes a normal request to the CDN.
    The editor, exercises, and checking code are embedded in this HTML file. The Python runtime is an external dependency. Programs are limited to 10 seconds per test and 20,000 output characters. Stop ends the worker, including an infinite loop. A new worker loads on the next run.
    Checks compare printed output, including capitalisation, spaces, and line order. Windows line endings are normalised, and a single final newline is ignored. Input prompts count as output, so use input() without a prompt. Passing the tests checks results, not the algorithm or coding style. Tests and expected answers are visible in the page source; this is a practice tool.
    Drafts and passed-exercise markers are stored in this browser on this device when browser storage is available. Nothing is saved to a class account. Only the Python standard library is intended for these exercises; graphical desktop apps and additional package installation are not included.
    

    Successful solutions are saved only after every test passes. Returning to a task after reopening this page restores its successful code; later drafts are kept separately and can be restored with Restore latest draft. A failed or stopped check does not replace the successful solution. Earlier pass markers without a verified code copy are retained; recheck once to save the successful code. Storage depends on the browser profile and website address. Clearing browser data removes progress; private browsing or disabled/full storage may prevent it being retained. For reliable persistence, use a consistent website address; storage for locally opened files can vary between browsers.
    Made for curiosity. Keep a downloaded copy of any code you want to retain.
