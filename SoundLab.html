Uncompressed sample data only. Compression, file headers and metadata change the stored file size.

01Samples in time

Sampling rate is measured in hertz (Hz). A lower rate captures fewer samples each second and limits high-frequency detail. Try 8,000 Hz with 24-bit resolution.

02Levels of amplitude

Sampling resolution is the number of bits per sample. n bits gives 2ⁿ possible amplitude levels. Try 4 bits at the highest rate and listen for quantisation noise.

03Make a prediction

What happens to raw file size when you halve the rate? What if you also halve the bit depth? Compare one setting at a time, then combine them.

Source information and how the simulation works

The original button plays the decoded audio. The processed version is resampled at the chosen rate, then rounded to 2ⁿ equally spaced amplitude levels, without dithering. Playback preserves pitch and duration, apart from rounding to the nearest whole sample. The browser converts both versions to your audio device’s output rate.

The waveform shows the first channel. Purple steps illustrate discrete stored values, not the exact reconstructed analogue signal. Lower-rate conversion uses the browser’s resampling implementation; exact filtering varies by browser. By the Nyquist limit, a rate of 8,000 Hz can represent frequencies below 4,000 Hz.

Most browsers decode audio into floating-point samples at a working rate. For supported WAV files, we preserve the header’s rate and report its stored bit depth. For compressed formats such as MP3, the working rate is labelled separately; there is no equivalent fixed PCM bit depth for the compressed data. The default 24-bit setting is a teaching model, not a claim about the original file. Increasing a setting cannot restore information already lost in a recording.

For responsive classroom use, files are limited to 30 MiB and the experiment uses up to the first 30 seconds and the first two channels. No audio is uploaded.
